# Расходы PRO — правила проекта (Spec Kit Constitution)

**Версия:** 1.0.0 · **Утверждено:** 2026-10-31 · **Статус:** пилот в отдельной ветке

## Обязательные принципы

### I. Сохранность финансовых данных
Никакое изменение UI, стилей, сборки или Spec Kit не должно удалять, сбрасывать, мигрировать или менять формат пользовательских расходов, доходов, категорий, настроек, экспортов либо локальной базы. Любые миграции данных требуют отдельной спецификации, резервного копирования и регрессионных тестов.

### II. Сохранение существующего стека
Фактический стек этого репозитория — Capacitor 8, веб-интерфейс в `www/`, нативный Android/SQLite-плагин в `native/`, сборка через GitHub Actions/Gradle. Нельзя менять стек, подключать новые UI-фреймворки или переписывать существующие части под Kotlin/Compose, Flutter или иной стек без отдельного доказанного основания.

### III. Утверждённый дизайн
Сохранять глубокий матовый 3D, сдержанные тени, тёплую нейтральную палитру, читаемость и существующие работающие переходы. Не возвращать яркий глянец, случайные градиенты, белые окантовки и чрезмерно контрастные кнопки. Проверять **все состояния** элементов и экраны, а не только главную страницу. Изменения дизайна согласовывать с утверждёнными референсами.

### IV. Анализ → спецификация → план → тест → минимальное изменение → сравнение
Перед правками изучать реальную ветку, инструкции `AGENTS.md`, исходники и `package.json`. Spec Kit отвечает за требования, планирование и задачи. Существующие Android Development Skills/AI-Council отвечают за recon, design, test, diff, performance по ситуации. Для исправления поведения сначала воспроизводить дефект, затем проверять регрессию. Запрещены несвязанные изменения.

### V. Проверяемая поставка
Использовать `npm run verify` и текущие CI-сценарии; по необходимости проверять APK на устройстве. Ни факт установки Spec Kit, ни наличие CI-файла не подтверждают успешную сборку APK или плавность 120 FPS. APK считать готовым только после сборки и проверки артефакта. Любое отсутствие проверки явно указывать.

## Правило применения
Этот документ управляет Spec Kit-планированием в рамках **данного репозитория**, не меняя другие проекты или глобальные настройки ChatGPT. Любой агент обязан прочитать `AGENTS.md` и этот документ до реализации.

## Изменения документа
Изменять через отдельный проверяемый diff с объяснением; не ослаблять принципы ради прохождения тестов.
